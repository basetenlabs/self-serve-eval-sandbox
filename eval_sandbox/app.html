Runs

How a run works

  1. Find. The repository's recent merged pull requests that change both code and tests. The PR's text, or the issue it closes, is the request; the code just before the merge is the starting point.
  2. Check. Each PR's tests must fail before the change and pass after it, in the same Blaxel image the models use. PRs that don't are left out: that's a setup problem, not a model's.
  3. Run. Each model works on each task in a fresh Blaxel sandbox through Claude Code, with GitHub and package registries blocked so it can't look up the answer.
  4. Grade. After deleting the agent's sandbox, a fresh verifier sandbox runs the PR's hidden tests against the model's change, then an AI judge compares it with the merged change. Solved means both agree.

Repository snapshots and execution artifacts are uploaded to your dedicated Blaxel workspace. Reports stay on this machine; code also goes to the model provider and diffs to the judge. Agent sandboxes are always deleted before verification; verifier sandboxes are deleted unless explicitly kept for debugging.

Runs are ordinary pr-eval run processes, so they keep going if this page is closed. The same works from a terminal: pr-eval run owner/repo --models claude-opus,deepseek-v4.1-flash.
